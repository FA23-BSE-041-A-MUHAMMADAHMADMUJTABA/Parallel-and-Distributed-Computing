1. SOCKET PROGRAMMING KIYA HAI?
--------------------------------------------------------------------------------
Network par do mukhtalif programs (jaise k Client aur Server) aapas mai data
kaise share karte hain?
Jawab hai: "Sockets" k zariye.

- Socket asal mai aik virtual endpoint ya darwaza (door) hota hai jahan se
  data network mai bheja jata hai aur receive kiya jata hai.
- Socket do cheezon se mil kar banta hai:
  1. IP Address: Machine (Computer) ka pata (jaise 127.0.0.1 jo local machine hai).
  2. Port Number: Computer k andar specific program (process) ka number (jaise 8888).

Client aur Server model mai:
- Server ek port par "Listen" (intezar) karta hai.
- Client us IP aur Port par "Connect" hota hai.


--------------------------------------------------------------------------------
2. PEHLE WALE CODE MAI KIYA PROBLEM / LIMITATION THI?
--------------------------------------------------------------------------------
Lab manual mai pehle jo example code diya gaya tha, usmai ye line likhi thi:
  message = recvall(sc, 16)
  print('The incoming 16-octet message says', repr(message))

Octet ka matlab hota hai 8 bits yani 1 Byte (English ka 1 character standard ASCII
mai 1 byte ka hota hai). Yani message ki lambai FIXED 16 characters thi.

Is fixed size ki waja se do baray maslay paida hotay the:
1. Chhota Message (Underflow):
   Agar client ne sirf 5 characters bheje maslan "Hello", to server `recvall(sc, 16)`
   par atak jata tha (block ho jata tha). Server baqi k 11 characters ka intezar
   karta rehta tha jo kabhi aane hi nahi the! Aakhir kaar jab socket band hoti,
   to EOFError aa jata tha.
2. Bara Message (Overflow / Truncation):
   Agar client ne 30 characters ka message bheja, to server sirf pehle 16 characters
   uthata tha aur baqi ka aadha message socket buffer mai phansa reh jata tha
   ya zaya ho jata tha.

Nateeja: Real world mai koi bhi insaan ya application hamesha 16 characters ka
jumla nahi bolti! Message kabhi 2 lafz ka hota hai, kabhi 100 lafz ka. Is liye
fixed 16-character limitation ko khatam karna zaroori tha.


--------------------------------------------------------------------------------
3. TCP PROTOCOL KA "BYTE STREAM" NATURE (ASAL WAJA)
--------------------------------------------------------------------------------
Aap soch rahe honge: "Server seedha hi pura message ek dafa mai kyu nahi parh leta?
Hume length bhejny ki zaroorat kyu pari?"

Ye network programming ka sab se ahem concept hai:
TCP (SOCK_STREAM) "Stream of Bytes" hota hai, "Message-oriented" nahi hota!

- Stream ka matlab hai paani ka nalka ya dhara!
  Jab aap nalka kholte hain, paani qatron ki shakal mai lagatar behta hai.
  TCP ko ye nahi pata hota k konsa jumla kahan shuru hua aur kahan khatam hua.
- TCP k andar koi "Message Boundary" nahi hoti.
- Agar client 3 alag alag messages bhej de: "Ahmad", "Mujtaba", "CS", to TCP server
  ko wo sab ek sath chipka kar "AhmadMujtabaCS" bana kar de sakta hai!
- Is maslay ko solve karne k liye hum Application Layer par "Message Framing"
  (Message ki hudood banana) use karte hain.


--------------------------------------------------------------------------------
4. SOLUTION: "LENGTH-PREFIX FRAMING" (HAMARA TASK)
--------------------------------------------------------------------------------
Message framing k dunya mai do baray tareeqay hotay hain:
A) Delimiter use karna: Har message k aakhir mai koi nishani laga do jaise '\n'
   (newline), lekin agar message k darmian mai hi '\n' aa jaye to masla hota hai.
B) Length-Prefix (Header + Body): Message k shuru mai bata do k aage aane wala
   message kitne characters ka hai!

Hamare Lab Task mai yahi tareeqa (Length-Prefix) istemal kiya gaya hai:
Hamara protocol do hisson par mushtamil hai:
  [ 3 CHARACTERS HEADER ] + [ VARIABLE LENGTH BODY ]

Example:
Agar message hai: "Good Morning"
Length = 12 characters.
3 Digits Header = "012"
Full Packet jo wire par jayega = "012Good Morning"

5. zfill() METHOD AUR 3 DIGITS KA CONCEPT
--------------------------------------------------------------------------------
Question: "zfill() kyu use kiya aur 3 digits hi kyu rakhe?"

1. 3 Digits Kyu?
   Task mai condition di gayi hai: "Assume max. number of length is 255 i.e. 3 digits".
   Chunkay maximum length 255 ho sakti hai, aur 255 mai 3 digits hotay hain (2, 5, 5).
   Agar hum 1 se 255 tak koi bhi number len, to wo zyada se zyada 3 digits ka hoga.

2. zfill() Kiya Karta Hai?
   `zfill()` Python ka built-in string method hai jo kisi string k shuru mai
   zeros (0) laga kar uski lambai required size tak pohanchata hai:
   - "7".zfill(3)   => "007"   (Length 3 ban gayi)
   - "45".zfill(3)  => "045"   (Length 3 ban gayi)
   - "210".zfill(3) => "210"   (Pehle se 3 digits hai, zero nahi lagayega)

3. Fixed Size Header Ka Faida:
   Kyun k header ka size hamesha 3 characters FIXED ho gaya, server ko pehle se
   maloom hai k usay sab se pehle sirf aur sirf 3 bytes parhni hain!
   Agar hum zfill use na karte aur sirf '7' bhejte, to server ko kaise pata chalta
   k header 1 digit ka hai, 2 digits ka hai ya 3 digits ka?
   zfill() ki waja se server bina kisi shak o shubha k pehle 3 bytes read karta hai,
   unko integer number banata hai, aur fir utnay hi bytes mazeed read kar leta hai.


--------------------------------------------------------------------------------
6. SERVER KA FLOW (DO-MARHALA RECEPTION)
--------------------------------------------------------------------------------
Server client se data do rounds mai receive karta hai:
1. Round 1:
   `recvall(sc, 3)`
   Server wire se theek 3 bytes uthata hai.
   In 3 bytes ko decode karke integer banata hai: `int("025") -> 25`.
2. Round 2:
   `recvall(sc, 25)`
   Server ko pata chal gaya k message 25 bytes ka hai, ab wo aglay exact 25 bytes
   uthata hai. Na 1 byte kam, na 1 byte zyada!

Is do-marhala process ko "Header Parsing and Payload Reading" kehte hain.


--------------------------------------------------------------------------------
7. REAL WORLD MAI YEH CONCEPT KAHAN USE HOTA HAI?
--------------------------------------------------------------------------------
Yeh sirf lab ka exercise nahi hai, balke internet ki bari protocols isi tarah
kaam karti hain:
1. HTTP Protocol (Web):
   Jab aap browser se koi web page open karte hain ya API call karte hain, to HTTP
   response mai ek header aata hai:
   `Content-Length: 3482`
   Browser pehle headers parhta hai, Content-Length se size nikalta hai, aur fir
   utna hi HTML body read karta hai!
2. Video Streaming & Files Transfer:
   Bari files ya videos bhejte waqt pehle file ka size (metadata header) bheja
   jata hai taake receiver ko pata ho k download kab mukammal hoga.
3. Database Drivers (MySQL / PostgreSQL):
   Python jab database se connect hota hai to queries aur results k packet headers
   mai length prefix hoti hai.
