1. `common/protocol.py` (FRAMING, HEADER FORMAT & RECVALL)
--------------------------------------------------------------------------------
Code Highlights:
  MAGIC_BYTES = b"DC"            # 2 Bytes Magic ("Distributed Compute")
  HEADER_FORMAT = "!2s2sI"       # Network Byte Order: 2s (Magic), 2s (Type), I (Length)
  HEADER_SIZE = 8                # Exact 8 bytes header length
  CHUNK_SIZE = 64 * 1024         # 64 KB chunk size for high-speed streaming

Working & Architecture:
- TCP Stream Fragmentation ka Hal:
  TCP data ko stream ki shakal mai bhejta hai baghair boundaries k. `HEADER_FORMAT = "!2s2sI"`
  har packet k start mai exact 8 bytes ka fixed header lagata hai.
  - `!`: Network Byte Order (Big-Endian) standards k mutabiq integers pack karta hai.
  - `2s`: Magic bytes (`b"DC"`). Agar incoming packet k pehle 2 bytes "DC" na hon to
          receiver foran reject kar deta hai (Security & Corruption Guard).
  - `2s`: Message Type Opcode:
      * `b"HS"` / `b"HA"`: Handshake SYN / ACK
      * `b"PI"` / `b"PO"`: Ping Request / Pong Response
      * `b"JS"` / `b"JA"`: Job Submit / Job Accepted
      * `b"FC"` / `b"FE"`: File Chunk / File End-of-File (EOF)
      * `b"PR"`          : Progress Telemetry Packet
      * `b"DR"` / `b"DC"`: Download Request / Download Chunk
      * `b"JR"`          : Job Final Result Packet
  - `I`: 4-byte unsigned integer jo payload length (0 se 4 GB) specify karta hai.

- `recvall(sock, num_bytes)` Function:
  TCP sockets par `sock.recv(num_bytes)` zaroori nahi k saray bytes ek hi dafa return kare.
  `recvall()` ek loop chalata hai:
  ```python
  buffer = bytearray(num_bytes)
  view = memoryview(buffer)
  received = 0
  while received < num_bytes:
      chunk = sock.recv_into(view[received:], num_bytes - received)
      if chunk == 0:
          raise ConnectionResetError("Connection closed unexpectedly")
      received += chunk
  return bytes(buffer)
  ```
  Yeh memoryview zero-copy slicing k sath guarantee karta hai k exact `num_bytes` receive hon.

- `send_packet()` & `read_packet()`:
  - `send_packet(sock, msg_type, payload)`: Header pack karta hai aur `sock.sendall(header + payload)`
    k zariye network buffer mai flush karta hai.
  - `read_packet(sock)`: Pehle `recvall(sock, 8)` call karta hai, magic aur length unpack karta
    hai, aur phir `recvall(sock, length)` k zariye pura payload return karta hai.

4. `server/network_server.py` (MULTI-THREADED SESSION HANDLER)
--------------------------------------------------------------------------------
- Main Listener Loop (`start()`):
  `self._server_sock.listen(10)` call karke incoming connections wait karta hai.
  Har client aane par:
  ```python
  handler_thread = threading.Thread(
      target=self._handle_client_connection,
      args=(client_sock, client_addr),
      daemon=True
  )
  handler_thread.start()
  ```
  Main listener thread kabhi block nahi hota; har client alag thread mai operate karta hai.

- `_handle_client_connection()`:
  - `sock.settimeout(None)`: Persistent interactive GUI sessions k liye idle timeout disable
    rakhta hai taake client jitni der marzi parameters choose kare, connection drop na ho.
  - Message Dispatch Loop:
    Packet type check karta hai:
    1. `MsgType.HANDSHAKE_SYN` -> Server specs aur capabilities ka JSON ACK return karta hai.
    2. `MsgType.PING_REQ`      -> Timestamps match karke pong response return karta hai.
    3. `MsgType.JOB_SUBMIT`    -> `_process_job_submission()` call karta hai.
    4. `MsgType.DOWNLOAD_REQ`  -> Finished rendered file client ko stream karta hai.
    5. `MsgType.CANCEL_REQ`    -> Task queue aur FFmpeg process ko kill karta hai.

- `_process_job_submission()`:
  1. Job metadata (file name, expected size, input SHA-256) read karta hai.
  2. Client ko `JOB_ACCEPTED` bhejta hai ("READY_FOR_UPLOAD").
  3. `FILE_CHUNK` packets loop mai receive karke disk par write karta hai aur simultaneously
     SHA-256 hasher update karta rehta hai jab tak `FILE_EOF` na milay.
  4. SHA-256 match karta hai. Match hone par task item bana kar `_stream_task_execution()` call karta hai.

5. `server/execution_engine.py` (FFmpeg NVENC GPU / CPU ENGINE)
--------------------------------------------------------------------------------
- `execute_video_transcode()`:
  1. Codec Selection:
     Agar `mode == "nvenc"` ya worker par GPU available ho:
     `codec = "h264_nvenc"`, `preset = "p4" / "p5"` (Pure Hardware NVENC).
     Warna CPU fallback:
     `codec = "libx264"`, `-threads {cpu_count}`.
  2. Command Generation:
     FFmpeg command build karta hai:
     `ffmpeg -y -i {input_path} -c:v {codec} -b:v {bitrate} -progress pipe:1 -nostats {output_path}`
  3. Progress Pipe Parsing:
     FFmpeg process ko `subprocess.Popen(stdout=subprocess.PIPE)` k sath spawn karta hai.
     `for line in process.stdout:` loop chalata hai aur stdout se `out_time_ms`, `fps`, aur `speed`
     extract karta hai.
  4. Real-Time Callback:
     Har progress tick par `progress_callback(percent, fps, speed, eta, status_text)` call karta
     hai jo network server k zariye client socket par telemetry JSON stream kar deta hai.

- `TaskItem` Class:
