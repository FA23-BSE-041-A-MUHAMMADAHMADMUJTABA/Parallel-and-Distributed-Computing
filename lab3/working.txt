2. THREAD LOCKS AUR SHARED STATE INITIALIZATION
--------------------------------------------------------------------------------
Code Lines:
  print_lock = threading.Lock()
  state_lock = threading.Lock()

  connected_clients = {}
  client_counter = 0

Explanation:
- `print_lock`: Jab multiple threads ek hi waqt mai screen par print karte hain,
  to unka text mix ho sakta hai. Yeh lock ek waqt mai sirf ek thread ko print
  karne deta hai.
- `state_lock`: `connected_clients` dictionary aur `client_counter` ko race
  condition se bachata hai.
- `connected_clients`: Is dictionary mai har active client ka ID, IP, Port aur
  assigned Thread Name store rehta hai.

3. safe_print() FUNCTION (ACQUIRE & RELEASE KA ISTEMAL)
--------------------------------------------------------------------------------
Code Lines:
  def safe_print(*args, **kwargs):
      print_lock.acquire()
      try:
          print(*args, **kwargs)
          sys.stdout.flush()
      finally:
          print_lock.release()

Explanation:
- Lab instruction ki requirement: "Lock (acquire() aur release()) ka istemal karein."
- Step 1 (`acquire()`): Pehle thread terminal screen par print karne ka exclusive right
  hasil karta hai. Agar koi doosra thread pehle se print kar raha hai, to yeh thread
  wait karta hai.
- Step 2 (`try` block): Message terminal par display hota hai aur `flush()` se buffer
  foran clear hota hai.
- Step 3 (`finally` block & `release()`): Kaam mukammal hote hi lock foran release
  ho jata hai taake agla thread print kar sake. `finally` block ensure karta hai k
  agar koi error bhi aaye, to lock hamesha release ho aur program deadlock na ho.

4. handle_client() WORKER FUNCTION KA STEP-BY-STEP FLOW
--------------------------------------------------------------------------------
Yeh function har client k liye ek naye alag thread k andar run hota hai.

Step 4a: Thread aur Client Details Extract Karna:
  current_thread = threading.current_thread()
  thread_name = current_thread.name
  client_ip, client_port = client_address

  - `current_thread.name`: OS scheduler is thread ko jo naam deta hai (e.g. "ClientThread-1-Port56616").
  - `client_address`: Client ka IP aur Port number.

Step 4b: Shared State mai Client Register Karna (with state_lock):
  state_lock.acquire()
  try:
      connected_clients[client_id] = {...}
      total_active_clients = len(connected_clients)
  finally:
      state_lock.release()

  - `state_lock.acquire()` karke dictionary mai entry add hoti hai aur
    `release()` se lock free hota hai.
  - Safe_print k zariye terminal par print hota hai:
    * Active Thread Name
    * Client IP
    * Client Port Number
    * Total Active Threads count (`threading.active_count()`)

Step 4c: Initial Welcome Banner Bhejna:
  client_socket.sendall(welcome_msg.encode('utf-8'))
  - Client ko ek welcome message bheja jata hai jis mai uska assigned thread name
    aur client id hoti hai.

Step 4d: Continuous Message Exchange Loop (`while True:`):
  - `raw_data = client_socket.recv(BUFFER_SIZE)`:
    Yeh call sirf is specific client k thread ko block karti hai. Main thread
    ya baqi clients k threads bilkul block nahi hotay!
  - Disconnect Check (`if not raw_data:`):
    Agar client ne terminal close kar diya, to loop break ho jata hai.
  - Exit Command Check (`client_message.lower() in ['exit', 'quit', 'bye']`):
    Agar user ne 'exit' ya 'quit' type kiya:
    1. Server client ko farewell message bhejta hai.
    2. Loop break ho jata hai.
  - Normal Message Reply (ACK):
    Agar normal message aaya, to server usko terminal par thread name aur client IP
    k sath print karta hai aur client ko ACK message return karta hai:
    `"Server ACK [Thread: ... | Client #...]: Received '...'"`

Step 4e: Connection Cleanup aur Thread Termination:
  finally:
      client_socket.close()
      state_lock.acquire()
      try:
          del connected_clients[client_id]
          remaining_clients = len(connected_clients)
      finally:
          state_lock.release()
      safe_print(...)

  - Socket ko close kiya jata hai.
  - `state_lock.acquire()` karke dictionary se client delete hota hai aur lock
    release hota hai.
  - Terminal par thread termination ka banner show hota hai:
    * Disconnected Thread Name
    * Remaining Active Clients
    * Total Living Threads

5. start_server() MAIN LISTENER LOOP AUR THREAD SPAWNING
--------------------------------------------------------------------------------
Code Lines:
  server_socket = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
  server_socket.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
  server_socket.bind((HOST, PORT))
  server_socket.listen(10)

Explanation:
- `socket.AF_INET`: IPv4 address family.
- `socket.SOCK_STREAM`: TCP protocol.
- `SO_REUSEADDR`: Taake agar server restart karein to "Address already in use" ka error na aaye.
- `server_socket.listen(10)`: Server incoming connections k liye listening state mai chala jata hai.

The Accept & Thread Spawning Loop:
  while True:
      client_socket, client_address = server_socket.accept()
      
      state_lock.acquire()
      try:
          client_counter += 1
          assigned_id = client_counter
      finally:
          state_lock.release()

      thread_name = f"ClientThread-{assigned_id}-Port{client_address[1]}"
      client_thread = threading.Thread(
          target=handle_client,
          args=(client_socket, client_address, assigned_id),
          name=thread_name,
          daemon=True
      )
      client_thread.start()

Kyunki Main Thread `client_thread.start()` karne k foran baad wapis `accept()`
par aa jata hai, is liye naye aane walay clients ko ZERO DELAY k sath accept
kar liya jata hai!

--------------------------------------------------------------------------------
9. TERMINAL PRINT SYNCHRONIZATION (print_lock)
--------------------------------------------------------------------------------
Masla:
Python ka standard `print()` function internally completely atomic nahi hota jab
multiple threads ek sath standard output (stdout) ko likh rahe hon.
Hal:
`safe_print()` mai har print call se pehle `print_lock.acquire()` aur baad mai
`print_lock.release()` hota hai. Is ki waja se terminal par aane walay logs
hamesha saaf, formatted aur line-by-line rehte hain.

--------------------------------------------------------------------------------
10. CLIENT STATE TRACKING (state_lock)
--------------------------------------------------------------------------------
Masla:
Agar do clients theek ek hi microsecond mai connect hon, to dono threads
`client_counter += 1` ko simultaneously read aur update kar sakte hain (Read-Modify-Write Race Condition).
Hal:
`state_lock.acquire()` lagane se counter aur dictionary updates atomic ban jatay hain,
jis se client IDs aur active connection count 100% accurate rehte hain.
