1. SOCKET PROGRAMMING KIYA HAI? (QUICK FOUNDATION)
================================================================================
Distributed Systems mai mukhtalif devices ya programs aapas mai network k zariye
baat-cheet (communicate) karte hain.

- Socket: Operating System (OS) ka wo software endpoint (darwaza) hai jis k
  zariye ek program network card (NIC) par data bhejta aur receive karta hai.
- Identification k 2 lazmi hissay:
    a) IP Address  : Machine ka address (jaise '127.0.0.1' localhost k liye).
    b) Port Number : Machine k andar chalne walay specific application ka number
                     (e.g., 8888), taake OS right program tak data pohnchaye.
- TCP (SOCK_STREAM): Connection-oriented protocol jo guaranteed, ordered aur
  reliable data delivery ensure karta hai.

2. SINGLE-THREADED SERVER KA MASLA (SEQUENTIAL & BLOCKING I/O)
================================================================================
Lab 02 mai humne Single-Threaded Server banaya tha. Uska sab se bara nuqsan
(limitation) yeh tha:

- Ek Waqt Mai Sirf Ek Client:
  Server ek loop mai chalta hai:
    Client 1 connect hua -> Server us se baat kar raha hai -> Client 1 disconnect hua -> Tab ja kar Client 2 ki bari aayegi!
- Blocking Calls (Head-of-Line Blocking):
  `socket.accept()` aur `socket.recv()` blocking operations hain. Jab tak
  Client 1 koi message nahi bhejta, server `recv()` par BLOCK (ruk) jata hai.
- Result:
  Agar Client 1 ghanton tak connect reh kar baitha rahe aur koi message na bheje,
  to dunya bhar k baqi hazaron clients wait mai atak jayenge (Starvation / Denial of Service).

3. MULTI-THREADING KIYA HAI AUR KYU ZAROORI HAI?
================================================================================
Is blocking maslay ko solve karne k liye hum Multi-Threading ka istemal karte hain.

- Thread Kiya Hai?
  Thread kisi process ka sab se chhota execution unit (lightweight sub-process)
  hota hai. Ek process k andar multiple threads ek hi memory space share karte
  hue aapas mai parallel/concurrent chal sakte hain.
- Multi-Threaded Server ka Falsafa:
  1. Main Listener Thread: Server ka main thread sirf darwazay par khara rehta hai
     aur naye connections (`accept()`) ka intezar karta hai.
  2. Worker Threads: Jaise hi koi naya client connect hota hai, main thread foran
     ek "Naya Thread" banata hai aur us client ka pura connection us thread k
     hawalay kar deta hai.
  3. Main thread foran wapis darwazay par chala jata hai taake agli request le sake!
- Nateeja: Har client ko lagta hai k server sirf usi k sath baat kar raha hai,
  aur koi bhi client doosray ko block nahi karta.

4. PYTHON "threading" MODULE AUR threading.Thread KA ROLE
================================================================================
Python ka built-in standard module `threading` multi-threading provide karta hai.

- Thread Creation:
    t = threading.Thread(target=handle_client, args=(client_sock, client_addr), name="ClientThread-1")
- Ahem Parameters:
    - target : Wo function jo is thread ne execute karna hai (jaise `handle_client`).
    - args   : Us function ko pass kiye jane walay arguments (socket, address).
    - name   : Thread ka custom readable name (debugging aur logging k liye).
- Lifecycle Methods:
    - `t.start()` : Thread ki execution shuru kar deta hai (OS scheduler ko invoke karta hai).
    - `threading.current_thread().name` : Current thread ka naam batata hai.
    - `threading.active_count()` : Kitne threads is waqt zinda (alive) hain unki tadad deta hai.

5. CONCURRENCY VS PARALLELISM (GIL AUR SOCKET I/O KA CONNECTION)
================================================================================
- Concurrency: Ek waqt mai multiple tasks ki progress ko manage karna (Interleaving).
- Parallelism: Ek hi second mai multiple tasks ka alag alag CPU cores par bilkul
  ek sath physically run hona.

Python mai GIL (Global Interpreter Lock) hota hai jo ek waqt mai sirf ek bytecode
instruction ko execute karne deta hai. Lekin SOCKET PROGRAMMING mai GIL masla
kyu nahi banta?
- Socket programming "I/O-Bound" (Input/Output bound) task hai, CPU-bound nahi!
- Jab koi thread `sock.recv()` par network data ka wait karta hai, Python GIL ko
  RELEASE (chor) deta hai!
- Doosra thread foran chal parta hai. Is tarah multiple clients bina kisi rukawat
  k 100% smooth concurrency k sath handle ho jatay hain.

6. RACE CONDITION AUR CRITICAL SECTION KIYA HOTAY HAIN?
================================================================================
Jab multiple threads ek hi shared memory ya resource ko simultaneously access
aur modify karne ki koshish karte hain, to maslay shuru hotay hain.

1. Critical Section:
   Code ka wo hissa jahan shared resource (e.g. Terminal screen, Shared Counter,
   Shared Dictionary) ko access ya update kiya ja raha ho.
2. Race Condition:
   Aisi situation jahan program ka output is baat par depend karne lag jaye k
   kaun sa thread pehle execute hua aur kaun sa baad mai!
   Example 1: Terminal Printing:
   Agar Thread 1 aur Thread 2 ek sath `print()` call karein, to dono k letters
   aapas mai mix ho jayenge: "HGerleloet iwnogrlsd" (Garbled Output).
   Example 2: Client Counter:
   Dono threads ne ek sath `counter += 1` kiya, dono ne purani value read ki aur
   increment kiya, to 2 naye clients aane k bawajood counter sirf 1 barha!

7. THREAD SYNCHRONIZATION: LOCK (MUTEX) KA CONCEPT
================================================================================
Race condition se bachne k liye hum "Thread Synchronization" karte hain. Iska
sab se bunyadi tool "Lock" (Mutual Exclusion / Mutex) hai.

- Lock ka Asal Asaan Matlab:
  Ek washroom ka single darwaza aur uski chaabi!
  - Jo shakhs andar jayega, wo pehle darwaza LOCK karega.
  - Jab tak wo andar hai, baqi sab bahar line mai WAIT karenge.
  - Kaam khatam hone k baad wo darwaza UNLOCK karega, phir agla shakhs andar ja sakega.

Python mai Lock banane ka tareeqa:
    my_lock = threading.Lock()

8. acquire() AUR release() METHODS KA KIRDAR AUR WORKING
================================================================================
Lab instructions mai explicitly require kiya gaya hai k Lock k `acquire()` aur
`release()` methods ko use kiya jaye.

1. `lock.acquire()`:
   - Yeh method lock hasil karne ki koshish karta hai.
   - Agar lock FREE hai, to current thread ko mil jata hai aur thread Critical
     Section mai dakhil ho jata hai.
   - Agar lock kisi doosray thread k paas pehle se LOCKED hai, to current thread
     wahin BLOCK (ruk) jata hai jab tak lock free na ho jaye.

2. `lock.release()`:
   - Critical section ka kaam mukammal hone k baad lock ko free (unlock) karta hai.
   - Jaise hi lock release hota hai, line mai khara agla waiting thread foran lock
     hasil kar leta hai.

3. Safe Programming Pattern (try-finally):
   Lock lagane k baad agar code mai koi exception ya error aa jaye, to lock
   hamesha k liye locked reh sakta hai (jisay "Deadlock" kehte hain).
   Is se bachne k liye hamesha standard pattern istemal karte hain:
   -----------------------------------------
   my_lock.acquire()
   try:
       # Critical Section (Shared Resource)
       ...
   finally:
       my_lock.release() # Lazmi release hoga
   -----------------------------------------

9. MULTI-THREADED TCP SERVER KI ARCHITECTURE
================================================================================
Lab 03 k code mai architecture is tarah design ki gayi hai:

         +------------------------------------------------+
         |               SERVER START                     |
         |         socket() -> bind() -> listen()         |
         +------------------------------------------------+
                                 |
                                 v
                     [ MAIN LISTENER THREAD ]
                                 |
                +----------------+----------------+
                |                                 |
         Client 1 Connects                 Client 2 Connects
                |                                 |
                v                                 v
   +-------------------------+       +-------------------------+
   |  Spawn Worker Thread 1  |       |  Spawn Worker Thread 2  |
   | Name: ClientThread-1... |       | Name: ClientThread-2... |
   +-------------------------+       +-------------------------+
                |                                 |
     handle_client() Loop              handle_client() Loop
                |                                 |
   [ Uses Lock for Prints/State ]    [ Uses Lock for Prints/State ]
                |                                 |
     Continuous Chat until 'exit'      Continuous Chat until 'exit'
                |                                 |
     Client Closes Connection          Client Closes Connection
                |                                 |
    Thread Cleaned Up & Exits         Thread Cleaned Up & Exits

10. ASAL ZINDAGI (REAL-WORLD) MAI ISKA ISTEMAL
================================================================================
1. Web Servers (Apache, Tomcat):
   Har aane wali HTTP request k liye naya thread ya worker pool banaya jata hai.
2. Chat Applications (WhatsApp Web, Discord, Telegram):
   Server hazaron users k sockets ko concurrent threads/event-loops k zariye
   handle karta hai taake real-time messages foran deliver hon.
3. Multiplayer Gaming Servers:
   Har player ki position aur actions alag thread/stream mai process hoti hain.
4. Database Connection Pools:
   Concurrent queries ko simultaneous process karne k liye locks aur multi-threading
   ka istemal hota hai.
